# Quincestone — Design System

## Character

Quincestone should feel premium, calm, precise, intelligent and operationally credible.

The public and operational products share identity but do not need identical density or layout.

## Avoid

- generic SaaS styling;
- crypto aesthetics;
- neon;
- glassmorphism;
- decorative dashboard noise;
- fabricated metrics or status;
- excessive gradients and animation.

## Prefer

- strong typography;
- disciplined spacing;
- restrained surfaces;
- clear hierarchy;
- accessible interaction states;
- responsive behavior;
- truthful loading, empty, error and success states;
- purposeful motion with reduced-motion support.

## Tokens

Use semantic design tokens for brand, background, surface, text, border, interaction, success, warning, error and information. Shared tokens belong in the existing shared configuration/UI system when multiple applications genuinely consume them.

## Product distinction

`apps/web` can use editorial composition, stronger storytelling and conversion-oriented rhythm.

`apps/app` should prioritize operational clarity, information density and fast decision-making.

`apps/admin` should prioritize internal control and system visibility.

The visual language remains one Quincestone across all surfaces.
